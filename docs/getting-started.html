Getting Started

Get up and running with Ignite in just a few minutes. This guide will walk you through installation, creating your first project, and understanding the framework structure.

Installation

Ignite requires Go 1.22 or higher. Install the Ignite CLI using Go's package manager:

go install github.com/sazzadh88/ignite/cmd/ignite@latest

PATH Setup

Ensure Go's bin directory is in your PATH so the ignite command is available globally:

macOS / Linux (zsh):

echo 'export PATH=$PATH:$HOME/go/bin' >> ~/.zshrc
source ~/.zshrc

macOS / Linux (bash):

echo 'export PATH=$PATH:$HOME/go/bin' >> ~/.bashrc
source ~/.bashrc

Windows (PowerShell):

[Environment]::SetEnvironmentVariable("Path", $env:Path + ";$env:USERPROFILE\go\bin", "User")

Windows (CMD):

setx PATH "%PATH%;%USERPROFILE%\go\bin"

Verify the installation:

ignite version

You should see the Ignite ASCII banner with version info.

Creating Your First Project

Create a new Ignite project using the CLI:

ignite new myapp

This command creates a new directory called myapp with a complete project structure. Navigate into your project:

cd myapp

Project Structure

Ignite follows Laravel's organizational conventions. Here's what you'll find in a new project:

myapp/
├── app/
│   ├── controllers/      # HTTP controllers
│   │   └── HomeController.go
│   ├── models/          # Database models
│   │   └── User.go
│   ├── middleware/      # HTTP middleware
│   │   └── Authenticate.go
│   ├── jobs/           # Background jobs
│   │   └── ProcessPayment.go
│   ├── policies/       # Authorization policies
│   │   └── PostPolicy.go
│   └── requests/       # Form request validation
│       └── CreateUserRequest.go
├── config/
│   ├── config.go       # Loads project config onto framework defaults
│   ├── app.go          # Application config (reads .env)
│   └── database.go     # Database config (reads .env)
├── database/
│   ├── migrations/     # Database migrations
│   │   ├── migrations.go   # package base (always present)
│   │   └── 2026_05_17_120000_create_users_table.go
│   └── seeders/       # Database seeders
│       └── UserSeeder.go
├── routes/
│   ├── web.go         # Web routes
│   └── api.go         # API routes
├── resources/
│   ├── views/         # HTML templates
│   └── assets/        # Static assets
├── storage/
│   ├── logs/          # Application logs
│   └── uploads/       # File uploads
├── ignite             # Project console (./ignite serve, migrate, ...)
├── ignite.bat         # Windows project console
├── .env               # Environment variables
├── go.mod
└── main.go            # Application entry point

Configuration

Ignite uses environment variables for configuration. The .env file in your project root contains all configuration values:

# Application
APP_NAME=MyApp
APP_ENV=local
APP_KEY=
APP_DEBUG=true
APP_URL=http://localhost
APP_PORT=8080

# Database (sqlite is the zero-config default)
DB_CONNECTION=sqlite
# DB_HOST=127.0.0.1
# DB_PORT=3306
# DB_DATABASE=myapp
# DB_USERNAME=root
# DB_PASSWORD=

CACHE_DRIVER=file
SESSION_DRIVER=file
QUEUE_CONNECTION=sync

# Mail
MAIL_MAILER=smtp
MAIL_HOST=127.0.0.1
MAIL_PORT=1025
MAIL_USERNAME=null
MAIL_PASSWORD=null
MAIL_FROM_ADDRESS="hello@example.com"
MAIL_FROM_NAME="${APP_NAME}"

The .env values are mapped into the config repository at bootstrap and read via app.Config() (Laravel-style) — never read the environment directly. Important: never commit .env to version control.

Generating an Application Key

Your application key is used for encryption. Generate a secure key from your project directory:

./ignite key:generate

This writes a base64: key into your .env. The development server will refuse to start until a valid APP_KEY is set.

Running the Development Server

Every project ships an ./ignite console (the project-local CLI). Start the built-in development server with:

./ignite serve

By default, your application will be available at http://localhost:8080. You can specify a different host or port:

./ignite serve --host=0.0.0.0 --port=9000

Your First Route

Let's create a simple route. Open routes/web.go and add:

package routes

import (
    "github.com/sazzadh88/ignite/http"
    "github.com/sazzadh88/ignite/routing"
)

func RegisterWebRoutes(router *routing.Router) {
    // Welcome page
    router.Get("/", func(req *http.Request) *http.Response {
        return req.JSON(map[string]interface{}{
            "message": "Welcome to Ignite!",
            "version": "0.1.0",
        })
    })

    // Hello route with parameter
    router.Get("/hello/{name}", func(req *http.Request) *http.Response {
        name := req.Param("name")
        return req.JSON(map[string]string{
            "greeting": "Hello, " + name + "!",
        })
    })
}

Visit http://localhost:8080/hello/World and you'll see:

{
  "greeting": "Hello, World!"
}

Your First Controller

Controllers help organize request handling logic. Create a new controller:

./ignite make:controller UserController

This creates app/controllers/UserController.go:

package controllers

import "github.com/sazzadh88/ignite/http"

type UserController struct{}

// GET /users
func (c *UserController) Index(req *http.Request) *http.Response {
    return req.JSON(map[string]string{
        "message": "List of users",
    })
}

// GET /users/{id}
func (c *UserController) Show(req *http.Request) *http.Response {
    id := req.Param("id")
    return req.JSON(map[string]string{
        "id": id,
        "message": "User details",
    })
}

// POST /users
func (c *UserController) Store(req *http.Request) *http.Response {
    // Create user logic
    return req.JSON(map[string]string{
        "message": "User created",
    })
}

Register the controller in routes/web.go:

router.Resource("/users", &controllers.UserController{})

This automatically registers all RESTful routes for your controller.

Database Setup

Ignite comes with SQLite configured by default. To use a different database, update your .env file:

MySQL

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=myapp
DB_USERNAME=root
DB_PASSWORD=

PostgreSQL

DB_CONNECTION=pgsql
DB_HOST=127.0.0.1
DB_PORT=5432
DB_DATABASE=myapp
DB_USERNAME=postgres
DB_PASSWORD=

SQLite is the zero-config default and needs no server. For MySQL/PostgreSQL just set DB_CONNECTION and the matching DB_* values — no code changes. (MySQL also supports DB_SOCKET for socket-only servers; Postgres DB_SSLMODE defaults to prefer — encrypted if the server supports it, plaintext otherwise.)

Run migrations to set up your database schema:

./ignite migrate

Useful CLI Commands

Ignite has two CLIs, following the Rails model:

  • Global ignite — the installer. Only ignite new, ignite version, and ignite upgrade.
  • Project ./ignite — shipped in every project root. Runs all project commands using the framework version pinned in that project's go.mod (no global reinstall needed).
Command Description
ignite new [name] Create a new project (global installer)
./ignite serve Start development server (requires APP_KEY)
./ignite key:generate Set the application encryption key
./ignite make:controller [name] Create a controller
./ignite make:model [name] Create a model
./ignite make:migration [name] Create a migration
./ignite make:middleware [name] Create middleware
./ignite migrate Run database migrations
./ignite migrate:rollback Rollback last batch
./ignite migrate:status Show migration status
./ignite db:seed Seed the database
./ignite queue:work Start queue worker
./ignite schedule:run Run scheduled tasks
